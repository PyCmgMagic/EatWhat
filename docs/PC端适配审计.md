# PC 端适配审计与整改结果

更新：2026-10-23。

首次审计发现的 28 个剩余入口已全部进入专门的桌面布局。新版接口接入后，手机登录/注册与设置密码恢复路径已可用，余下 9 个入口继续提供待接入状态说明。新增搜索、收藏、口味偏好和作者编辑使用原生响应式页面。接口实施结果见 [新版接口接入与验证](新版接口接入与验证-20261023.md)。

## 已完成的适配

| 分组           | 页面与路由                                                            | 当前桌面布局及操作                                                                                                |
| -------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 通知           | `/notifications`                                                      | 消息列表与说明双栏；支持分页、逐条/全部已读、本页未读筛选、准确的菜品或店铺跳转                                   |
| 认证           | `/verify`                                                             | 设置侧栏、认证状态、POST 获取本次统一认证链接、邮箱入口与状态刷新；Mock 不发送真实邮件                            |
| 账号           | `/settings/account`                                                   | 紧凑信息行、绑定状态、密码及设备入口；跨站授权按需展开加载                                                        |
| 密码           | `/settings/password`                                                  | 根据 hasPassword 提供首次设置或原密码修改，也可获取验证码设置新密码；失败保留输入                                 |
| 隐私           | `/settings/privacy`                                                   | 公开范围开关、未保存提示和统一保存；不将未知状态默认为关闭                                                        |
| 手机绑定       | `/settings/bind-phone`                                                | 设置侧栏与验证码表单，继续复用现有绑定流程；Mock 禁用真实绑定                                                     |
| 他人主页       | `/users/:id`                                                          | 左侧资料与关注操作，右侧公开关系和分享统计；尊重列表公开范围；他人分享列表仍待接口开放                            |
| 关注与粉丝     | `/follows`                                                            | 宽屏列表、当前页搜索、分页与类型切换；未公开的他人列表不发读取请求                                                |
| 新建店铺       | `/restaurants/new`、`/restaurants/new/details`                        | 合并为同页表单，填写店名、地址和实际 GCJ02 坐标；失败保留输入，未知提交暂停重复创建；成功后把返回 ID 直接带入发布 |
| 说明           | `/settings/about`、`/data-notice`                                     | 品牌介绍、紧凑内容行及适合阅读的正文，统一设置导航                                                                |
| 账号入口       | `/auth`、`/auth/password`、`/auth/username-register`、`/auth/consent` | 原生桌面双栏及表单，支持校验、错误反馈、防重、授权分支与登录后返回目标页                                          |
| 手机账号与恢复 | `/auth/register`、`/auth/register/confirm`、`/auth/forgot`            | 手机验证码登录并自动注册；找回密码引导先手机登录，再进入验证码设置密码                                            |
| 新版主流程     | `/search`、`/favorites`、`/settings/preferences`、`/foods/:id/edit`   | 筛选工作区、多列菜品、偏好表单和作者编辑；在四种 PC 宽度检查通过                                                  |

桌面配色、字体、圆角、按钮及圆盘插画与已完成的主流程保持一致。设置页面共享持续可见的侧栏，各页有清晰的标题、返回入口、状态和对应操作；常规内容高度随内容变化，不再固定为 844px。

## 验证结果

- `desktop-secondary.js`：28 个入口分别在 1024、1280、1440、1920px 检查，共 112 项；没有旧画板容器、横向溢出或空白页。
- 同脚本另验证 6 个代表页面的 760px 强制桌面缩放、3 个移动端原画板、专用登录/注册表单及 Mock 登录；没有未捕获页面异常。
- `desktop-secondary-api.js`：拦截 36 次请求、15 次写操作，覆盖密码、隐私、通知、关注、列表隐私、手机绑定、店铺创建和注册登录；无远程请求，无未约定接口调用。
- 故障场景包括失败保留输入、修正重试、双击防重、秒/毫秒通知时间、同 ID 不同目标、分页切换、新店结果未知时跨路由暂停。
- `mock-login.js`：退出刷新、目标页恢复、PC 与移动端 Mock 登录、会话隔离、生产默认禁用 Mock 均通过。
- 上述二级页脚本为原适配阶段历史记录。当前新版 42 项单元/契约测试、81 个服务操作检查和生产构建通过；另补充 16 项 PC 新页面宽度检查与新版拦截流程。首包体积提示仍存在，真实后端端到端联调尚未完成。

## 边界与保留项

首页、附近、搜索、菜品与餐厅详情、个人中心、收藏、标签、足迹、资料编辑、发布裁剪、设置首页继续使用已有原生桌面布局。菜品评论为本地 Mock，地图选点、他人菜品列表等缺口仍需接口或服务支持。

位置、筛选、标签、举报等临时面板继续采用居中桌面对话框，内部复用现有控制器。`/design`、`/reference/*` 等设计对照入口有意保留移动画板；`/admin` 沿用表格管理布局，不属于本次产品页面迁移范围。移动端主流程及原型对照不受此次布局分发影响。
