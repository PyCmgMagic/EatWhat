# APIv6 逐项接入规划与验收

日期：2026-11-08。目标是在现有移动原型、桌面布局和统一权限处理上接入用户提供的 APIv6；保留此前未提交的地图、定位和页面修改。先完成本规划，再依次实施与验证。生产发布不在本次范围。

## 逐项分析与决策

| 变化 | 当前影响与接入决策 | 验证重点 |
| --- | --- | --- |
| POST /user/activity | 新增统一前台活动入口，仅有效登录用户在进入或回到前台时调用；合并重复事件、限频、不定时轮询。无请求体，经验以服务端为准，不做“领取经验”按钮。 | 游客、后台、管理员操作页不报；账号切换、卸载、失败、连续焦点事件不串号、不重复弹窗。 |
| GET /user/growth | 个人中心增加成长入口与成长页，展示等级、累计经验和升级进度。沿用现有奶油白、暖黄、深棕色和字体，使用餐碗图形与清晰进度条；不改变个人中心原型主体。 | 初始加载、失败重试、缺字段、满级、账号切换；不在前端写死等级门槛。 |
| GET /user/growth/ledger | 成长页分页展示经验来源、所属业务日期、实际入账时间，空记录有明确说明。 | 下一页、返回上一页、空页、后台刷新失败保留数据。 |
| GET /admin/engagement/stats | 内容与运营管理增加活跃统计，支持查询日期，分别说明当日、完整自然月、截至所选日的 30 天去重人数。 | 角色守卫、未来日期限制、日期切换、0 值与失败状态；不把 MAU 当作日活之和。 |
| GET /auth/callback | 后端学校回调，不新增前端 API 调用；审计归入后端回调。 | 固定回调不能被误认作客户端缺失接口。 |
| POST /auth/callback | 同上；保留学校表单回调语义。 | 不由浏览器模拟提交学校 code/token。 |
| GET /callback | 同上；新学校 code 交换链路仍由后端完成。 | 前端仅处理最终结果提示并重新查询账号认证状态。 |
| POST /callback | 同上。 | GET/POST 四项均被契约审计正确分类。 |
| 设置登录名保留会话 | 按 reauthenticationRequired 显式判断；false 时更新账号资料、保留登录并返回账号页或首次设置后续流程。旧 true 分支继续兼容；修改演示响应和文案。 | token 不丢失、资料刷新、true 兼容分支、刷新失败不把成功写操作重提。 |
| 注销 deletePostsAndComments | 默认匿名保留正文和图片；提供显式删除选项及解释。选择保存在当前恢复命令中，开始提交后锁定；恢复文件携带该选择。 | 省略/false 与 true 的准确提交；错误或不确定结果、页面返回、导出导入不改变原选择。所有测试拦截请求。 |
| 菜品 user 作者对象 | 统一作者展示适配：优先有效 user，兼容旧 uploaderName/accountId；显式 user=null 时不制造可访问的作者资料链接。 | 新对象、null、缺失、昵称空值与旧返回格式；手机及桌面一致。 |
| loginId 收窄为 string | 更新生成类型和断言，保留已有会话 token 解析。 | 不把账号标识强转数字。 |
| 7 个模型名删除及其余模型调整 | 重新生成类型；按现有操作路径和参数保留功能，不因 DTO 名消失删除功能。 | 类型检查、全部 service 契约 fixtures、推荐数组/分页双格式兼容。 |
| 30 项公开语义与 security 冲突 | 生成器显式处理公开与可选登录说明；保持游客浏览，并用测试锁定。API 基址继续 /api。 | 游客读取不被阻断，需学生认证的写操作仍统一引导。 |
| 元数据与能力开放差异 | 使用文件路径和实际操作清单识别 APIv6，保留原始文档；通知等待页及既有活动模块排除范围不变。 | 生成、审计、测试均从同一份 APIv6 读取；不因“已部署”说明自动开放其他入口。 |

## 实施顺序

1. 契约基础：统一文档源、生成 schema/权限、更新审计分类与类型断言。
2. 现有流程：登录名、注销选择、作者适配和学校认证错误说明。
3. 新增能力：service 与演示数据、统一活动入口、成长页面及入口、管理员统计。
4. 验收：契约与单元测试、隔离浏览器检查手机/桌面与错误分支、生产构建；记录真实后端联调限制。

浏览器验收同时修复了旧版重登录分支的导航竞态：清除会话会触发原受保护页面的登录入口，可能覆盖目标路由。现先发起导航，旧页面的自动登录入口在地址已改变时不再抢占；重登录仍保留新登录名预填。320px 的成长分页保持单行，成长入口也加入独立的移动原型个人中心。

## 入口与复现

- 普通用户：个人中心 → 我的成长（`/#/me/growth`）；桌面侧栏、手机个人面板和功能导航都有入口。无需学生认证，仍需有效登录。
- 管理员：内容与运营管理 → 活跃统计（`/#/admin/v4?tab=engagement`）。管理员身份来自账号查询，服务端负责最终授权。
- 现有设置：账号与安全 → 设置登录名；注销账号 → 已发布内容处理选项。
- `npm run api:diff` 生成 `output/api-v6-diff-20261108.json`；`npm run api:audit` 生成 `output/api-v6-coverage-20261108.json`（路径相对于仓库根目录）。
- 启动 `npm run dev` 后，在独立 Playwright CLI 浏览器会话中执行 `run-code --filename=scripts/api-v6.js`、`run-code --filename=scripts/verification-callback.js`（工作目录为 `frontend/`）。脚本自行创建并关闭隔离上下文，拦截业务请求；截图输出 `frontend/output/playwright/api-v6-*.png`。

## 实际边界

本次完成前端契约接入、交互与模拟端到端验证，尚未使用真人账号验证线上等级入账、管理统计或注销。接口是否注册、后台数据口径及学校真实 code 交换仍取决于部署和配置，需要在目标环境联调。APIv6 的文档元数据版本未更新、30 项公开说明与 security 不一致，以及推荐返回数组/分页差异均已在适配与核查中记录。通知等待页和此前排除的活动业务维持原范围。

接入验收阶段未执行推送或生产部署。随后用户要求将地图、APIv6 和菜品插画统一整理后提交到 `main`，范围及发布边界见 [本轮变更整理](本轮变更整理-20261108.md)。日志、截图、覆盖报告与构建包在忽略目录中，不包含真实账号操作数据。
