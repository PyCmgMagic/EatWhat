
开发和预览共用此代理目标。运行中的开发服务已自动重启并加载新配置。新域名的证书校验已恢复，政策与校区接口经本地代理返回 HTTP 200、业务码 0。

登录 403 已定位为 CORS。新网关当前允许的来源包含旧站点 `https://v50to.you`，把浏览器 Origin 改成 `https://eat.v50to.you` 会被拒绝。开发和预览代理现移除浏览器 Origin，以服务端请求访问上游。带本地 Origin 的空登录请求经代理返回 HTTP 200、业务码 10001（参数非法），已能进入后端参数校验。代理来源头处理已加入回归测试。真实账号登录尚待验证，生产跨域直连仍需后端配置实际前端来源。

以下为 2026-10-23 旧地址 `https://v50to.you/api` 的历史配置与验证记录。

## 已配置

本机 `frontend/.env.local`：

```dotenv
VITE_API_BASE_URL=/api
API_PROXY_TARGET=https://v50to.you/api
```

`.env.example` 同步了该地址。开发服务已自动重载，Vite preview 已重启。两者使用同源代理：

| 浏览器本地路径                | 上游真实地址                                   |
| ----------------------------- | ---------------------------------------------- |
| `/api/foods/list`             | `https://v50to.you/api/foods/list`             |
| `/api/campus/list`            | `https://v50to.you/api/campus/list`            |
| `/api/api/location/provinces` | `https://v50to.you/api/api/location/provinces` |

代理只替换本地第一层 `/api`，不会去重控制器自带的 `/api`。兼容旧的 Origin-only 目标，未配置目标时不会启用远程代理。代理调整请求的 Host 和存在的 Origin，使其对应上游网关。

真实模式：`http://127.0.0.1:5173/?demo=0&view=desktop#/search`。默认和 `?demo=1` 继续使用独立 Mock 数据及会话。

上表路径相对于当前基地址。开发代理和浏览器实际读取校区、菜品均正常，`latest-api-gateway.js` 返回 `backendHealthy: true`；没有未捕获页面异常，返回 Mock 首页后推荐也正常。

先前 `90004 未捕获异常` 来自旧基地址对应的请求；改用当前地址后，上述公开接口均成功，之前的后端异常结论不再适用于当前配置。

带本地 Origin 的跨域直连 GET / OPTIONS 仍返回 HTTP 403、`Invalid CORS request`。同源开发代理已避免本地页面的跨域阻断；该配置不代表生产跨域权限已开放。
