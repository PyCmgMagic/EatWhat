# PC 端设计与实现

更新：2026-10-23。沿用本地 `prototype/` 的移动端视觉语言，新增适合鼠标、键盘和宽屏浏览的布局；继续使用 v2 数据层。

剩余二级入口已补齐桌面布局：设置子页、认证、通知、他人主页、关注与粉丝、新建店铺、登录注册与说明页，共 28 个入口。功能待接入的 12 个入口采用明确的开放状态页，不伪造数据或提交。完整清单与验证结果见 [PC 端适配审计与整改结果](PC端适配审计.md)。

## 设计方向

延续移动端的「一道主角菜 + 白色内容抽屉」。PC 端将圆桌舞台横向展开，让标题、价格、操作和盘子各有位置；内容以多列浏览，个人操作以侧栏导航组织。

核心颜色为 ink `#231C18`、paper `#FFFFFF`、mist `#F4EFEB`、muted `#6E625B`，舞台沿用原型九色，包括 broth `#F3C46E`、mango `#FFCB45`、tomato `#C9442B` 等。中文 Noto Sans SC，标题字重 900；价格、计数使用 Bricolage Grotesque。复用原始 MingCute 图标、圆盘插画和厚度胶囊按钮。

```text
顶部：品牌 / 发现、附近、我的 / 搜索 / 通知 / 发布 / 头像

发现： [ 菜名、价格、操作    横向圆桌与大圆盘 ]
       [ 白色抽屉：分类标签                  ]
       [ 菜品       菜品       菜品       菜品 ]

附近： [ 店名搜索、店铺列表 ][ 示意地图 + 选中店铺 ]
我的： [ 个人信息、操作侧栏 ][ 上传 / 收藏、多列菜品 ]
详情： [ 大圆盘舞台        ][ 信息、互动、标签、描述 ]
发布： [ 照片预览与缩略图  ][ 菜名、价格、分类、发布 ]
```

## 布局与交互

- 顶部固定导航，页面宽度上限 1512px，常规左右留白 48px；1024px 屏幕收紧到 30px。
- 首页宽幅舞台与白色抽屉，四列菜品。支持换一道、指示点、鼠标拖动和键盘左右键，舞台色随当前菜变化。
- 附近左侧独立滚动店铺列表，右侧保留同风格地图示意；选店与浮层联动，明确标注真实地图待接入。
- 菜品详情左右分栏，支持收藏、点赞、公共/个人标签和多图查看；餐厅页提供店内菜品、发布与坐标导航。
- 食友讨论直接位于菜品详情下方：左侧评论、附图与楼内回复，右侧固定当前菜品摘要及输入框；旧评论入口回到对应菜品，不再单独显示原型评论页。当前交互为明确标注的本地 Mock。
- 个人中心采用左侧资料卡和导航、右侧三列内容。收藏分类明确限定当前页。
- 我的标签和足迹复用个人中心侧栏。标签为双列管理卡片，重命名就地完成；足迹分菜品/店铺，按日期以双列图文记录展示，保留分页和本页关键词筛选。
- 编辑资料使用独立桌面页：左侧头像与实时主页预览，右侧双列表单；昵称、签名、性别、生日与家乡同页编辑、一次保存。头像支持拖放与就地裁剪，选择时只改预览。
- 发布使用同页工作区：左侧搜索与选择餐厅，中间照片和舞台色，右侧菜名、价格、分类、推荐理由与摘要。裁剪在弹窗内完成，支持拖放、多图管理和封面选择。
- 登录使用舞台插画与表单双栏；设置按账号、隐私和关于分组，退出使用确认弹窗。
- 标签等临时选择在桌面改为居中对话框，保留圆角、遮罩、键盘焦点与 Esc 关闭。
- 新增 PC 页面复用同一 API、会话、草稿和标签状态，移动端保留原有 51 张源画板及样例对照入口。

- PC 设计预览：<http://127.0.0.1:5173/?demo=1&view=desktop>。窄的预览区域以 1280px 画布缩放显示，便于看到完整 PC 页面。

普通访问按窗口宽度自动选择布局；上述 view 参数用于开发预览，不改变后端身份。原始设计对照页始终显示原始画板。

- `frontend/scripts/desktop-tabs.js`：主导航和内容标签切换专项，覆盖快速往返、布局稳定、加载保留内容、缩放预览、键盘与减少动态效果。
- `frontend/scripts/desktop-secondary.js`、`desktop-secondary-api.js`：28 个入口的四种桌面宽度、缩放和移动端回归，以及 36 次拦截接口请求的关键操作与故障恢复。

已验证 1024、1280、1440、1920px 宽度；主要页面无横向溢出，无未捕获异常或 React 警告。37 项单元/契约测试与生产构建通过。构建保留现有首包体积提示，真实设备性能与后端端到端联调尚未验收。

首页切换已修复：主图和下一道预览使用独立位置，避免 1600px 以上断点覆盖；所有推荐图按菜品 ID 保留节点，切换只改变位置、大小与透明度，连续操作可接续当前过渡，取消每次重建时从透明开始的入场动画。左右拖动在清空手势起点前计算方向，避免状态更新时误读空值。专项验证覆盖 1024、1280、1440、1599、1600、1920、2560px；连续切换无图片节点重建及全透明空帧，菜名、图片和详情链接一致。

截图在 `output/playwright/pc-*.png`。接口缺失项继续显示待接入，PC 设计不代表评论、举报、地图、设备管理等后端能力已上线。

顶部导航、首页分类和「上传 / 收藏」使用同一套持续滑动指示器（220ms），内容采用 180ms 的小幅位移与透明度过渡；连续操作接续当前动画，不等待退出动画。标签使用固定字号与计数宽度，分类内容保留高度，避免标签横移与页脚跳动。「上传 / 收藏」加载期间保留上一份列表并标记正在切换，新数据就绪后更新。动画只改变 transform 与 opacity；键盘切换和减少动态效果偏好即时完成。已验证 4 种常见桌面宽度及 760px 缩放预览。

复现时先运行 `npm run dev`，再在仓库根目录使用独立 Playwright CLI 运行脚本；发布脚本出现文件选择器时执行 `upload prototype/assets/photos/sq_luosi.png`。验收使用隔离演示数据，之后运行 `prototype-cleanup.js` 清理固定测试内容。

## 发布工作区与连贯性

PC 的 `/publish`、`/publish/dish`、`/publish/crop` 统一为同一个发布工作区，选店和编辑不再分步跳转；从餐厅详情「加一道菜」进入会带入该餐厅，同时保留已有菜品内容。裁剪支持拖动、缩放、恢复原图和取消，应用时复用原文件重新取景。舞台色及摘要实时反映编辑内容，底部显示待完成项与上传进度。

当前草稿跨页面保留，刷新页面会清空；界面已说明。上传仍为 presign → 不带应用令牌的原始 PUT → complete → 保存 key。支持零元、选填价格、部分上传后复用 key、双击防重、未知创建结果跨导航锁定和人工核实后恢复。新版创建返回 ID，成功后直接进入准确详情；初始公共/个人标签、舞台色、候选色、饭点与裁剪信息随创建保存。移动端继续沿用源画板流程，并支持发布表单滚动及饭点多选。

发布专项为 `desktop-composer.js`、`desktop-composer-api.js`、`desktop-composer-context.js`，均在仓库根目录执行。API 故障验收拦截全部请求，验证未知结果、业务失败、重试和存储 PUT 隔离，没有真实后端写入。PC 发布脚本直接设置文件输入，不需要手动处理文件选择器。截图为 `output/playwright/pc-composer-*.png`。

## 个人资料桌面编辑

PC 的 `/me/edit` 与原补充资料入口 `/me/details` 统一使用完整表单，未认证用户也可编辑。左侧保持实时预览，右侧将基本资料和补充资料分组，底部统一显示未保存状态、取消修改、保存进度与成功反馈。保存后留在当前页，可继续修改或返回个人主页；从页内返回时会提醒放弃未保存内容，刷新时也有保护。

头像先在本地裁剪、缩放和预览，保存时才执行 avatar 上传与资料更新；业务失败保留输入与已上传 key，再次保存不会重复上传。仅提交变化字段，避免因地区列表加载失败或生日返回格式不同而覆盖原值；换省后要求选择有效城市。新版尚未约定性别、生日与省市的清空方式，因此会阻止未经约定的空值写入。原移动端流程保留。

专项脚本为 `desktop-profile.js`、`desktop-profile-api.js`，覆盖实时预览、校验、取消恢复、裁剪取消/应用、统一保存与回读、旧入口、未认证用户、四种桌面宽度、760px 缩放预览和移动端回归。接口故障验收拦截 17 次请求，验证 5 次资料更新与 1 次存储 PUT，无远程后端请求。截图为 `output/playwright/pc-profile-*.png`。

## 上传菜品图片的一致展示

默认菜品使用原型中的透明盘子插画，用户上传的普通照片采用圆形裁切与白色盘沿。卡片内两者使用相同尺寸和位置，不再把照片铺满矩形卡片；背景优先使用云端舞台色并兼容旧本机选择。移动端列表和真实接口模式也使用同一规则。原照片与取景文件不在展示时改写，普通照片不会自动变成插画或抠图。

默认插画按图片来源及菜名共同识别，避免上传菜品与默认菜品重名时被错误套用插画样式。`desktop-food-photos.js` 使用隔离演示数据验证四种桌面宽度、重名、推荐、详情及移动端，无真实后端请求。截图为 `output/playwright/pc-food-photo-*.png` 和 `mobile-food-photo-cards.png`。

## 菜品页内讨论

PC `/foods/:id` 下方新增「吃过的人说」，支持最有用/最新排序、点赞、展开回复、图文评论与图片大图预览。右侧编辑区始终保留所讨论菜品的图片、名称和餐厅；点击详情中的「食友讨论」只定位到同页，旧 `/comments?foodId=:id`、`/comments/write?foodId=:id` 自动进入对应菜品，写评论入口会聚焦输入框。「我的 → 评论」展示自己的评论与回复记录，每条记录回到准确的菜品讨论。

当前最新 JSON 契约仍没有评论 API，因此这些可操作内容仅在 Mock 模式开启，存放在独立的 `eatwhat-demo-comments-v1` 本地存储中；评论按菜品 ID 隔离。支持 500 字、3 张图片、刷新恢复、双击防重及 Ctrl+Enter 发表。新上传菜品默认没有示例评论。页面明确提示本地演示范围，真实模式不显示示例评论，禁用输入与发表，并且不调用未经约定的评论接口。移动端保留原始画板流程。

代码为 `frontend/src/desktop/FoodDiscussion.tsx`、`discussion.css` 和 `frontend/src/demo/comments.ts`。`desktop-discussion.js` 验证完整本地交互、旧入口、我的评论、按菜品隔离、4 种桌面宽度及 760px 缩放预览；`desktop-discussion-api.js` 拦截真实适配层 4 次只读请求，确认无评论 API 和远程写入。导航与标签动画回归通过，移动端详情保留。截图为 `output/playwright/pc-dish-discussion.png` 和 `pc-dish-with-comments.png`。

## 标签与足迹桌面适配

`/me/tags` 和 `/history` 使用原生桌面布局，顶栏统一选中「我的」，保留个人资料侧栏和当前菜单。标签卡片展示名称、使用次数与就地重命名/删除操作，失败保留输入；删除前说明仅移除标签关联，收藏与菜品保留。个人标签从菜品详情或初始发布创建，收藏入口现已按标签查询全部收藏，不再只筛当前页。

足迹按浏览日期分组，菜品与店铺分别分页，切换类型回到第 1 页；加载时保留上一份内容。记录支持本页关键词筛选，使用真实目标类型和编号跳转；失效内容、编号不匹配或不安全编号不提供错误链接。时间兼容 epoch 秒/毫秒，并对未知或异常未来时间标记待确认。当前没有清空足迹接口，因此不提供伪清空操作。Mock 补齐直接进入店铺时的足迹记录，读取菜品页的店铺地址不会生成店铺足迹，旧菜品足迹继续兼容。

代码为 `frontend/src/desktop/DesktopLibrary.tsx`、`library.css`、`history.ts`。专项脚本 `desktop-library.js` 验证标签重命名、取消、删除与收藏保留，菜品/店铺记录、筛选和准确跳转，4 种宽度 × 2 个页面、760px 缩放预览及移动端回归；`desktop-library-api.js` 拦截 14 次请求，覆盖分页、PUT 失败恢复、删除空尾页返回、失效记录与类型切换，3 次标签写请求均为拦截响应，无远程后端写入。截图为 `output/playwright/pc-library-tags.png`、`pc-library-history.png`。
