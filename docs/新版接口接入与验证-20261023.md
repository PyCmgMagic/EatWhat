# 新版接口接入与验证

本轮已按用户范围补充 17 项，当前覆盖 98/126 个操作；活动不接，密码冲突与账号安全复核暂缓。详见 [剩余接口接入与验证](剩余接口接入与验证-20261023.md)。

日期：2026-10-23。唯一现行契约为 `EatWhat 业务服务 API.openapi.json`，版本 `dual-site-multiwriter-v73-20261023`。旧 YAML 只保留作历史对照。

## 已完成接入

| 能力           | 实现与入口                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全站菜品搜索   | `/search` 支持菜名、分类、区域、预算与排序；省略 `restaurantId` 查询全站，筛选在服务端分页前执行。店铺查询使用无需定位的 `/restaurant/browse`。                           |
| 完整收藏筛选   | `/favorites` 使用服务端关键词、分类、预算、排序与个人标签条件；从「我的标签」进入时查询全部收藏，不再只筛当前页。                                                         |
| 校区和饭点推荐 | 读取 `/campus/list`，推荐传入 `campusId`、`mealTime`、`category`、`size`；游客生成本机 `deviceId`，支持换一批。                                                           |
| 发布与新建店铺 | 消费创建响应的 `data.id`，菜品发布后直达准确详情；新店创建后自动带入发布。初始公共标签 ID、个人标签名与菜品一起提交。                                                     |
| 作者管理       | 菜品详情提供「编辑菜品」「删除」；只允许已认证作者操作，使用 `/foods/my/{id}` 的 PUT / DELETE。PC 与移动端均可使用。                                                      |
| 云端展示信息   | 创建和编辑提交舞台色、候选色、饭点、裁剪参数；读取时优先使用云端设置。保存 `pictureKeys`，不把临时签名 URL 当作写入 key。                                                 |
| 图片读取       | 保留上传三阶段协议；签名图片加载失败时每张图片最多触发一次详情/列表刷新，防止失败循环。                                                                                   |
| 手机登录与注册 | `/auth/register` 使用 `/auth/phone/code`、`/auth/phone/login`；处理新账号、会话与授权同意分支，保留原用户名注册入口。                                                     |
| 验证码设置密码 | `/settings/password` 根据 `hasPassword` 提供首次设置或原密码修改；也可通过 `/auth/password/code`、`/auth/password/reset` 设置新密码。找回入口先引导手机登录，再进入设置。 |

| 推荐口味偏好   | `/settings/preferences` 接入 GET / PUT / DELETE `/user/recommendation-profile/preferences`，支持喜欢、不喜欢及清空手动偏好。                                              |
| 权限与兼容     | 游客可浏览公开内容；收藏仅要求登录，点赞、标签和发布仍遵守认证要求。补充账号安全业务码，保留 401/403 既有会话处理。                                                       |

移动端保留原型视觉与裁剪流程，发布内容区支持滚动，新增公共标签数量增加时仍可访问所有选项；PC 使用原生桌面工作区。新增共享页面分别适配两种屏幕。

## 数据与失败处理

- 重新生成 OpenAPI 类型；服务层共覆盖 98 个操作。请求字段遵守新契约，历史响应中可空字段在读取模型中兼容，不把可空规则扩展到请求体。
- 创建响应必须包含有效正整数 ID；即使业务码成功，缺失 ID 也按结果不确定处理，暂停重发，避免重复创建。
- 上传成功的 key 在失败重试中复用。存储 PUT 不携带应用会话头。仅修改文字时保留已有图片 key、裁剪与展示设置。
- 本地裁剪已经写入图片文件，上传后的封面参数保存中心 `(0.5, 0.5)`、直径 `1`，避免重复裁剪。普通照片使用圆盘样式，当前不会自动抠图。
- 新接口未约定清空性别、生日、省市的写法，因此禁止把空值保存成「已清空」的假成功；旧时间戳生日保持原值。
- API 失败保留输入；作者删除失败展示提示，不产生未处理 Promise 异常。

## 尚需实际部署验证与剩余缺口

当前网关及真实政策正文的公开读取已经验证。登录注册已加入主动勾选和当前版本提交，见 [政策同意接入](登录注册政策同意接入-20261023.md)。完整业务联调仍需要测试账号、生产跨域与存储配置。需要验证真实短信频控、认证回调、签名图片过期刷新和实际推荐结果。Mock 的推荐只演示条件过滤，不实现服务端的个性化算法和日级去重。

当前文档仍未提供完整的评论、举报、反馈、设备会话、换绑手机号、屏蔽、注销、通知偏好、专题与他人菜品列表协议；相关界面保持待接入，评论仅提供独立的本地演示。匿名未登录重置密码没有独立协议，当前采用手机登录后设置密码。地图仍为示意图，自动抠图未实现。

生产构建通过，但现有首包仍触发大于 500 kB 的提示，后续可做路由拆包。该提示不影响本次接口接入构建结果。
