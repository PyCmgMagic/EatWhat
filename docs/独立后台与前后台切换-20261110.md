# 独立后台与前后台切换

## 交付范围

后台统一使用 `/#/admin` 及其子路由，具有独立侧栏、页头与工作区，不显示前台导航、页脚或移动端底栏。继续使用现有字体、MingCute 图标和细分隔线，后台采用深色侧栏、暖白内容区和黄色选中态。

前后台属于同一前端应用，复用现有登录与 API，不需要重新登录或单独部署服务。后台模块按需加载，未登录、非管理员或封禁账号不会挂载管理内容或发起管理查询；服务端继续执行最终权限校验。

| 导航分组   | 模块与路由                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 工作台     | 数据概览 `/admin`、活跃统计 `/admin/engagement`                                                                      |
| 内容管理   | 菜品 `/admin/foods`、餐厅 `/admin/restaurants`、公共标签 `/admin/tags`、区域 `/admin/hubs`、校园专题 `/admin/topics` |
| 审核与反馈 | 内容审核 `/admin/moderation`、评论审核 `/admin/comments`、反馈举报 `/admin/feedback`                                 |
| 账号管理   | 用户管理 `/admin/users`、账号安全复核 `/admin/security`                                                              |
| 站点运营   | 公告 `/admin/announcements`、远程配置 `/admin/config`、版本 `/admin/versions`、配置审计 `/admin/audit`               |

现有内容维护、审核命令、删除确认及接口参数保持原有业务行为。校园专题页保留校区选择，编辑草稿按校区隔离；评论审核仍只提供待审图片张数，不假造图片预览。

## 切换与兼容

- 管理员在前台桌面页头、个人中心侧栏或手机个人中心点击「管理后台」，在后台页头点击「返回前台」。普通用户不显示切换入口。
- 切换复用当前登录，会分别记住前台页面与后台模块；已有列表筛选、分页和专题草稿通过原管理状态机制保留。专题草稿的编号、修订号、正文、时间、菜品与封面均按校区保存。
- 非敏感工作状态使用当前标签页的 `sessionStorage`，按账号及真实/演示模式隔离；目的地址仅允许站内且属于对应工作区。存储内容不能授予管理员权限。
- 前台根工作区保持挂载，保留现有发布草稿机制；前后台切换标记复用已有页面返回关系与滚动记录，避免返回详情后将后台当作前台父页面。
- `/admin?tab=restaurants&keyword=…` 自动迁移为 `/admin/restaurants?keyword=…`；`/admin/v4?tab=comments` 自动迁移为 `/admin/comments`。旧 `/admin/v4` 默认进入反馈举报。
- 桌面和平板显示固定侧栏；760px 及以下使用抽屉。抽屉打开时锁定背景滚动、禁用背景交互，支持 Escape 关闭与焦点恢复，放大到桌面宽度后自动关闭。支持减少动态效果和跳到管理内容。

## 代码入口

- `frontend/src/admin/AdminApp.tsx`：后台布局、权限状态、分组导航、校区选择与移动抽屉。
- `frontend/src/admin/WorkspaceSwitch.tsx`：管理员前后台切换入口。
- `frontend/src/app/admin-routes.ts`：模块定义、旧路由兼容与目的地址校验。
- `frontend/src/app/admin-state.ts`：账号隔离的工作区记忆与现有管理状态。
- `frontend/src/pages/Admin.tsx`、`frontend/src/features/v4/Admin.tsx`：保留原业务模块，移除双后台各自的导航外壳。
- `frontend/src/mobile/App.tsx`：按路由挂载前台或后台外壳，保留共享会话、草稿和确认弹窗。

未修改原型生成文件；没有重新引入单站清理时移除的跨站授权或活动管理功能。演示活跃统计的管理员判断同步使用演示身份，避免演示管理员进入该模块时被误拒绝。

本轮没有发布生产环境或使用真实管理员写入；真实后端部署和账号权限仍需在测试环境联调。浏览器移动端验收为模拟视口与键盘操作，尚未替代实体设备验收。

## 本地复验

启动前端后打开 `http://127.0.0.1:5173/?demo=1&persona=admin#/admin`。通过 Playwright CLI 打开同源页面，再执行：

```powershell
npx --offline --yes --package @playwright/cli playwright-cli -s=eatwhat --raw run-code --filename frontend/scripts/admin-workspace.js
npx --offline --yes --package @playwright/cli playwright-cli -s=eatwhat --raw run-code --filename frontend/scripts/api-v7.js
```

在 `frontend/` 运行 `npm test`、`npm run typecheck`、`npm run api:access:check`、`npm run api:audit` 与 `npm run build`。截图、日志、浏览器上下文及构建包均为本地产物，不提交 Git。
