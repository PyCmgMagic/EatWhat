# APIv7 接入与验收

当前接口来源为 `EatWhat 业务服务 APIv7.openapi.json`，OpenAPI 3.0.1，共 193 个路径、224 项操作、330 个模型。文件中的内部版本号尚未更新，不能用 `info.version` 区分 v6 与 v7。

## 已接入功能

| 功能                 | 接口                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 评论列表、发布       | `GET /foods/{foodId}/comments`、`POST /foods/{foodId}/comments`                          |
| 回复列表、发布       | `GET /comments/{commentId}/replies`、`POST /foods/{foodId}/comments/{commentId}/replies` |
| 食友晒图             | `GET /foods/{foodId}/gallery`                                                            |
| 我的评论、本人删除   | `GET /comments/submissions/my`、`DELETE /comments/{commentId}`                           |
| 点赞状态、点赞、取消 | `GET /comments/{id}/like`、`PUT /comments/{id}/like`、`DELETE /comments/{id}/like`       |
| 评论审核             | `GET /admin/comments/moderation/queue`、`POST /admin/comments/moderation/review`         |

新增 12 项均有接口封装及当前页面调用。客户端操作覆盖为 201 项，保留 9 项后端回调和 14 项既有活动接口排除项。

生成类型、权限规则、契约测试和审计读取 v7。模型重命名同步到原有适配层，不恢复单站清理时移除的跨站授权与同步页面。

## 页面与数据约定

- 桌面菜品详情保留左侧讨论、右侧编辑器；新增评论／晒图切换、排序、分页、按需读取回复及图片预览。
- 手机菜品详情显示两条评论预览；`/comments?foodId=…` 为全部评论，`/comments/write?foodId=…` 为发布／回复。发布页在窗口跨断点变化时保留当前编辑器。
- 两端的 `/me/shares?tab=comments` 显示全部个人审核状态、原因、图片张数和删除操作。旧手机 `/me?tab=comments` 地址重定向到此处。
- 管理员在 `/admin/v4?tab=comments` 审核评论，支持契约定义的通过、驳回、隐藏、恢复及删除；删除保留确认。
- 当前用户资料读取 `level` 和 `totalExperience`，成长接口继续提供进度阈值；他人主页在接口返回等级时展示等级。
- 正文必填，上限 200 个 Unicode code point，最多三张图。图片走现有压缩、预签名、PUT、完成确认流程，只向评论接口提交 `comments/` key。部分图片上传失败时保留已完成 key，重试不重复上传成功的图片。
- 评论、回复、删除及点赞写入使用 UUID `Idempotency-Key`。审核的 UUID 放在请求体 `decisionId`。结果未确认时冻结原始内容和 UUID，允许原命令重试。
- 文字评论与点赞需要登录，图片上传需要学生认证。公开列表可匿名读取；登录用户读取时继续带会话。
- 待审核内容不会加入公开讨论或晒图。评论时间按 ISO 时间解析；签名图片加载失败时按地址限制自动刷新一次，避免循环请求。
- 草稿按账号、菜品和回复对象隔离；登出、过期、切换账号时清理评论草稿和命令状态。正式接口失败不会回退演示数据。

## 文档所限的展示范围

公开评论只有作者昵称，没有头像、账号 ID 或回复总数。头像使用昵称首字，不构造作者主页链接；回复数量在读取该列表后展示。

我的提交与审核队列只有正文和图片张数，没有待审核图片地址，因此审核页用 info 提示图片无法预览。此版本没有新增图片审查接口，也不把公开图片墙当作待审核图片来源。

## 验证方法

2026-11-10 验证结果：59 个测试文件、506 项测试全部通过；TypeScript、权限规则检查、接口覆盖审计和生产构建通过。浏览器两组脚本覆盖五种宽度及权限、异常场景，均无运行错误，真实后端业务请求为零。手机列表末行可完整滚动到固定输入栏上方。

最新构建包为 `output/packages/20261110-103650.zip`，约 6.97 MB；生产构建没有新增动态导入警告。

在 `frontend/` 执行：

```powershell
npm test
npm run typecheck
npm run api:access:check
npm run api:audit
npm run build
```

浏览器验收先打开本地开发页，然后在仓库根目录通过 Playwright CLI 运行：

```powershell
npx --offline --yes --package @playwright/cli playwright-cli -s=eatwhat-v7 open 'http://127.0.0.1:5173/?demo=1#/foods/1'
npx --offline --yes --package @playwright/cli playwright-cli -s=eatwhat-v7 --raw run-code --filename frontend/scripts/api-v7.js
npx --offline --yes --package @playwright/cli playwright-cli -s=eatwhat-v7 --raw run-code --filename frontend/scripts/api-v7-edge.js
```

`api-v7.js` 使用独立浏览器上下文，覆盖 360、390、768、1280、1440px；手机与桌面覆盖回复、点赞取消、草稿、审核通过后公开及本人删除。`api-v7-edge.js` 使用请求拦截验证 404、403、非零业务码、过期图片、游客登录引导及未认证用户权限。

单元测试补充覆盖 Unicode 长度、图片 key、权限、原命令重试、重复点击、账号变化、局部上传失败与评论审核生命周期。截图及 JSON 验收结果保存在 `output/playwright/api-v7-*`，覆盖报告为 `output/api-v7-coverage-20261110.json`。

本次验收采用隔离演示或请求拦截，真实后端业务写入为零。线上路由启用情况、真实账号、图片存储及管理员权限仍需在后端测试环境完成联调。
