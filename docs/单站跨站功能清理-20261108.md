# 单站模式清理记录

## 核查依据

- APIv6 对部署状态的说明为“已部署到唯一海外业务站”。注册与手机登录 DTO 的 `crossBorderConsent`、`consentPolicyVersion` 均不是必填字段。
- 2026-11-08 只读检查线上 `/api/auth/consent/policy`，仍返回 `cross-border-preferences-v3` 与旧政策正文地址。`/api/remote-config` 没有提供可用于判断双站授权是否启用的开关。
- 因此，本次按当前单站产品要求移除前端跨站功能，不能据此断言服务端已删除这些接口或解除所有历史账号限制。本仓库没有后端代码，也没有更改服务器配置。

## 修改范围

- 手机登录页、桌面登录页和登录弹窗移除跨站政策勾选、正文弹窗及恢复授权流程。
- 密码登录、手机号验证码发送和登录、兼容的用户名注册不再依赖旧政策请求；注册请求不补填任何跨站同意字段。
- 设置、账号安全、功能目录移除跨站授权入口；管理后台移除跨站同步工作台和政策编辑器，历史 `tab=sync/policy` 展示概览。
- 删除旧授权页面、proof 临时状态、撤回表单、相关样式、政策正文加载器及其专用 DOMPurify 依赖。
- 历史 `/auth/consent`、`/auth/consent-offer`、`/auth/withdraw-consent` 链接使用替换历史记录的跳转：游客回密码登录，登录用户回账号设置；安全的站内 `next` 可继续使用。
- 学生认证、人机验证、隐私可见性、账号安全恢复和使用统计自主授权保持独立。
- 只有 `code=0` 且包含明确有效登录会话的响应建立会话。旧 `20005/20006` 或仅包含 proof／身份协调状态的响应显示账号不可登录提示，既不自动授权，也不进入旧恢复页面。

## 协议与历史资料

服务端尚在 APIv6 中声明的跨站接口类型、兼容适配及隔离 Mock 契约测试保留，业务页面不再调用。原始接口文档、设计原型和历史双站验收记录保留作为来源资料，不代表当前产品入口。历史双站 UI 专项脚本不再作为单站验收依据；当前回归入口为 `frontend/scripts/single-site-auth.js`。

## 验证

- 类型检查通过；47 个测试文件、405 项单元测试通过；生产构建通过。
- 浏览器专项 19 组检查通过、无页面异常，在 320、390、1440 px 下拦截全部业务请求，验证三种登录、验证码发送与倒计时、设置和后台、旧链接、旧 proof 失败及请求体字段。桌面真实登录表单弹窗也验证了成功后保留来源页。旧跨站接口请求数为零。
- 不执行真实短信、邮件、注册或真实账号写入。线上真实登录是否仍被旧服务端授权条件拦截，需要实际账号联调后才能确认。
