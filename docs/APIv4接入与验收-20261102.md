## 已有流程调整

- 菜名按 Unicode code point 校验 1–12 字，说明最多 300 字，价格必填且为 0–999、最多一位有效小数；个人标签规范化空白后 1–10 字，最多 20 项。
- 餐厅新名称 1–20 字、地址 1–30 字。菜品替换图片为 1–9 个 `foods/` key，餐厅替换门头最多 1 个 `restaurants/` key。
- 编辑未变化的历史超限值和旧图片引用时省略对应字段，不要求重传或删图；说明可通过空串清空。
- 创建和编辑保留 id、moderationStatus、revisionId；私有修订受理不显示为公开发布完成。临时审核图片按需获取，仅保留在当前页面内存并按有效期移除。
- 资料裁决使用当前 expectedRevision 和 heads 中的 selectedHeadId，目录裁决继续使用自身协议；封禁支持 ISO 8601 截止时间。

## 状态、凭据与隔离

- 404/405/501 明确显示未开放；403 保留会话并显示权限错误。409 保留输入，等待重新读取比较。网络或 5xx 写入结果不确定时阻止重复提交，不自动重放。
- 反馈提交和处理使用 Idempotency-Key；专题、设备、推送、换绑及注销保留各自命令标识和版本信息。
- 只有 READY 且返回有效 tokenName/tokenValue 的会话恢复结果才登录。恢复能力、同意 proof、受理结果和同步进度均不当作登录令牌。
- 恢复凭据使用独立请求头或指定请求体，不进入 URL、日志及浏览器普通存储。可以由用户主动保存恢复文件，重新打开页面后手动导入。Mock 持久化恢复命令的 SHA-256 摘要，原始能力凭据仍不自动持久化。
- 换绑发送验证码每次重新取得 CAPTCHA，取消或卸载会中止；成功后启用重发倒计时。
- 统计默认关闭；显式同意后仅提交预设事件、随机事件 ID 和同意修订号，不附带自由文本、网址或用户标识。关闭后停止发送。
- `?demo=1` 为独立 Mock，演示图片保存为隔离 key；真实模式不会回退 Mock。网页没有有效设备推送令牌时，登记成功仅表示绑定已受理。

## 验证

- `npm run api:generate`：由当前 YAML 生成类型。
- `npm run api:audit`：185 项封装，新增 68 项全部存在页面调用位置；报告 `output/api-v4-coverage-20261102.json`。
- `npm run api:diff`：APIv3 的 136 项增加到 APIv4 的 204 项，新增 68、删除 0。
- `npm test`：27 个文件、161 项测试通过，覆盖历史值编辑、幂等、修订冲突、私有审核、能力凭据隔离、恢复状态、CAPTCHA 一次性使用及统计关闭。
- `npm run typecheck` 与 `npm run build`：通过。
- `scripts/api-v4-flows.js`：12 组完整流程，包括发布到审核公开、账号恢复，以及 390px 九个页面布局。
- `scripts/api-v4-unread.js`：2 组，确认页头使用卡片未读数，标记已读后与列表即时同步；旧计数仅在新接口未开放时兼容。
- `scripts/api-v4-admin-errors.js`：9 组专题与运营管理、320px 管理页，以及拦截响应下的 403/404/409/503、远程关闭与草稿保留检查。

浏览器检查没有页面异常，也没有向外网发送请求；真实模式测试由本地拦截响应提供，没有真实账号写入。

## 部署边界

文档注明新增 68 项在 2026-10-30 核对时尚未在两站上线。本轮完成前端接入与隔离验证，没有探测或发布真实服务。实际可用性仍需后端注册对应路由、开启配置并完成业务联调。`VITE_BUILD_NUMBER` 可配置 Web 构建号以启用更新判定。真实系统推送还需要设备推送令牌与服务端配置；真实评论 CRUD 未在此契约提供，继续保持现有边界。
