## 1. 审计结论与覆盖

- `docs/openapi.json` 包含 **129 个 path、147 个 HTTP operation**。其中 **8 个**是学校 SSO 的四条 callback 兼容路径 × GET/POST，直接供业务客户端调用的是 **139 个**；本文逐项列完 147 个。
- 25 个 OpenAPI tag 的操作数之和为 147：Verification 14、User 12、Preference 3、Restaurant 14、Hub 6、Food 16、Comment 9、AdminRemoteConfig 8、AdminAi 3、AdminUser 6、Contact 11、Upload 3、Telemetry 1、Recommend 4、Push 6、Notification 4、Feedback 8、DeviceSession 3、Auth 5、Consent 3、AdminConsent 3、Taste 1、RemoteConfig 1、History 2、Campus 1。
- OpenAPI 是测试启动应用后从 `/v3/api-docs` 生成，并用 `operation-names.tsv` 强制每个 operation 都有名称、名称表也没有废弃项。来源：`@v2:src/test/java/you/v50to/eatwhat/OpenApiDocIT.java#L130-L167`；`@v2:src/test/resources/openapi/operation-names.tsv#L1-L168`。
- **不能把 OpenAPI schema 当作完全可信的 Java DTO 映射**：springdoc 把多个同名 nested record 合并为同一个 schema。本文清单中的请求/响应已经按控制器泛型和 DTO 源码纠正，完整偏差见第 6 节。

## 2. 通用协议、权限与错误

### 2.1 基址、认证和响应

- 公网基址是 `/api`，网关剥掉 `/api` 后进入应用。认证头是 `satoken: Bearer <tokenValue>`；会话最长 30 天、3 天无活动失效，允许多设备且不共享 token、不读 cookie。`@v2:src/test/java/you/v50to/eatwhat/OpenApiDocIT.java#L80-L91`；`@v2:src/main/resources/application.yml#L32-L39`
- 除 8 个 SSO callback 和远程配置的 304 外，业务 JSON 为 `Result{code,data,msg,timestamp}`；通常 HTTP 200，`code=0` 才成功。`@v2:src/main/java/you/v50to/eatwhat/common/Result.java#L6-L40`
- 路由不存在、方法不支持、媒体类型错误分别是 HTTP 404/405/415，并包装业务码 `10004/10004/10001`。限流返回 `10003` 且有 `Retry-After`。`@v2:src/main/java/you/v50to/eatwhat/common/GlobalExceptionHandler.java#L24-L29`、`#L80-L97`
- 权限记法：`公开` 不要求 token；`登录` 对应 `@SaCheckLogin`；`verified/admin` 是角色 OR；`admin` 是管理员。有效登录请求还会复检封禁和当前政策同意，未同意时为 `20009`，只有标记 `@ConsentExempt` 的接口放行。非 `/admin` 的正常登录请求会记录当天活跃。`@v2:src/test/java/you/v50to/eatwhat/OpenApiDocIT.java#L99-L123`；`@v2:src/main/java/you/v50to/eatwhat/account/config/AccountStatusInterceptor.java#L14-L48`

### 2.2 常用业务码

| code | 含义 | 典型场景 |
|---:|---|---|
| `10001/10002/10003` | 参数非法/缺失/频率过高 | 枚举、交叉字段、分页、限流 |
| `20001/20004/20009` | 未登录/角色不足/政策已更新 | 登录、verified/admin、重新同意 |
| `20006` | 数据同步中 | 远程配置乐观锁 revision 冲突，需重读 |
| `30001/30002/30003/30004/30005` | 用户不存在/禁用/用户名占用/密码错/验证码错 | 账号流程 |
| `30012/30013` | SSO state 无效/学号已绑定 | 学校统一认证 |
| `30014/30015/30016` | 用户名注册关闭/需验证码/验证码无效 | 注册、登录风控 |
| `40001/40002/40004` | 操作失败/状态不允许/重复提交 | 所有权、状态机、幂等冲突 |
| `40008/40009/40010/40016` | 菜品/店铺/商圈不存在/同店同名菜已存在 | 内容域 |
| `50001..50004` | 外部依赖失败 | AI、学校、短信、人机验证 |

### 4.4 远程配置的客户端处理顺序

1. 带缓存的 `GET /remote-config?platform=<android|ios|web>&build=<非负整数>&campusId=...`；保存 `ETag`，下一次发 `If-None-Match`。
2. HTTP 304 时没有 `Result` body，继续使用缓存；HTTP 200 时读取 `configVersion/flags/params/announcements/maintenance/versions/update`。
3. `update.decision=FORCE` 表示 `build<minBuild`，`SUGGEST` 表示 `build<latestBuild`，否则 `NONE`。
4. `flags` 固定五项 `publish,newShop,comment,push,topic`；maintenance 只是客户端提示，不能假设后端会替客户端拦写操作。

来源：`@v2:src/main/java/you/v50to/eatwhat/remoteconfig/dto/RemoteConfigDtos.java#L10-L33`；`@v2:src/main/java/you/v50to/eatwhat/remoteconfig/controller/RemoteConfigController.java#L31-L55`；`@v2:src/main/java/you/v50to/eatwhat/remoteconfig/service/RemoteConfigService.java#L107-L140`。
