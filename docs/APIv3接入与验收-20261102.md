# APIv3 接入与验收

日期：2026-11-02。当前契约为 `EatWhat 业务服务 APIv3.openapi.json`，版本 `user-blocks-consent-20261026`。APIv2 保留作历史差异对照。

## 修复内容

- `api:generate`、契约测试、全量覆盖审计及当前差异命令均以 APIv3 为目标。新增 `scripts/audit-api-v3.mjs`，归一化可空值和排他边界的格式差异；原 APIv2 对比脚本保留作历史工具。
- `consent()` 使用独立的 `ConsentStatusViewResponse`，只读取 `status`、`identityReady`、`policyVersion`。授权面板移除“注册已接受”，分别展示授权政策版本和当前政策版本；未知身份状态显示“待确认”。PC、平板与手机共用该组件。
- Mock 的 GET 查询明确投影三个字段，没有同意记录时返回 `NOT_GRANTED`、`false` 和当前政策版本。旧的六字段本地记录继续可用，上传数据保留；授权和两种撤回动作仍返回六字段进度，不与 GET 查询混用。
- 重新生成登录响应类型，`SaTokenInfoResponse.loginId` 和 `PhoneLoginDataResponse.loginId` 均为字符串；登录会话继续只接受明确的 token 信息。

## 可空引用生成兼容

APIv3 使用 `$ref` 与 `nullable: true` 组合。当前 `openapi-typescript` 会优先处理引用，忽略其可空标记，直接使用 CLI 生成会令足迹摘要与类型分支产生冲突，并丢失其他引用字段的 null 类型。

`scripts/generate-api.mjs` 在内存中把该组合转换成等价的 `anyOf: [引用, null]`，再通过现有生成器输出 `src/api/schema.d.ts`。不修改原始 APIv3 文件，不手改生成类型。类型回归检查覆盖足迹模型非 never、封面裁剪可为 null、三字段查询类型和字符串登录 ID。

## 验证结果

- 24 个测试文件、141 项测试通过。新增三字段查询、非零业务码与缺失数据拒绝、Mock 无记录默认值、旧政策记录、六字段授权/撤回响应以及上传保留检查。
- TypeScript 检查与标准生产构建通过。
- 覆盖审计通过：136 项操作中，117 项客户端操作、5 项后端回调、14 项既定排除的活动操作；本次没有新增或删除操作。
- 隔离浏览器验证通过：Mock 三字段查询、真实适配层三字段响应、授权政策与现行政策不同版本、授权与撤回后的查询刷新、503 失败及重试恢复、屏蔽列表成功响应。
- 检查 320、390、820、1440px，授权面板没有横向溢出。页面未捕获异常为 0；两次授权/撤回写入均由本地测试拦截，真实外部请求为 0。未执行真实账号登录、跨站授权或屏蔽写入，不将文档中的部署说明作为本次生产联调结果。

## 复现

```powershell
Set-Location frontend
npm run api:generate
npm run api:audit
npm run api:diff
npm test
npm run build
```

浏览器专项为 `frontend/scripts/api-v3-consent.js`，从仓库根目录通过 Playwright CLI 的 `run-code --filename` 执行。当前服务继续使用现有同源代理与显式 Mock 开关。
